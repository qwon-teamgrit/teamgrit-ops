# TeamGRIT Ops Work Agent PoC

## Goal
Add an experimental agent path to the existing `업무` tab without replacing the current production workflow.

The agent receives a meeting/work memo and uses only the already-synced TeamGRIT central data to propose net-new work items.

## Current system that must be preserved
- Existing TeamGRIT Ops web UI and Vercel deployment
- Google OAuth per browser/session
- Central Google Sheet as state/store
- `Projects`, `Tasks`, `Approvals`, `Executions`, `Customers`, `ProductFacts`, `Results`, `Sources`
- Existing `AI 업무 후보 생성` flow remains available as fallback
- User approval is required before writing Tasks/Approvals
- Never invent project, owner, due date, source, or status when evidence is absent
- Never auto-execute external actions from this PoC

## PoC input
- Free-form meeting/work memo entered in the existing `업무` textarea

## PoC tools / data
Read-only during analysis:
- Projects
- ProductFacts
- Sources metadata/evidence
- Existing Tasks for duplicate detection

Write only after explicit user approval through the existing UI:
- Tasks
- Approvals
- Executions

## PoC behavior
1. Understand the memo and identify likely work statements.
2. Match each statement to actual central Projects/ProductFacts/Sources evidence.
3. Compare against existing Tasks and suppress duplicates.
4. Propose only net-new, executable work units.
5. Preserve unknown owner/project/due date as `확인 필요` rather than guessing.
6. Return evidence/source IDs with each candidate.
7. Stop before registration and wait for the user's existing approval UI.

## PoC output
For each candidate:
- title
- project
- owner
- dueDate
- status
- reason
- sourceEvidence
- sourceIds
- duplicateStatus

Also return an agent trace summary for UI/debugging:
- matchedProjects
- existingTaskChecks
- proposedCount
- suppressedDuplicateCount
- modelUsed

## Safety / guardrails
- Central source evidence is authoritative; do not use unstated general knowledge as fact.
- No Task/Approval/Result mutation during analysis.
- No Gmail send, Calendar changes, Drive writes, or external execution in this PoC.
- Any future mutation still requires explicit human approval.

## Deployment choice
Prototype only. Do not migrate or replace the existing Vercel production runtime yet.

## Success criteria
- Agent PoC can analyze the same memo as the current AI path.
- It returns only evidence-backed tasks.
- Existing matching Tasks are suppressed rather than duplicated.
- User can compare current AI output and Agent PoC output in the `업무` tab.
- No change to current production Task approval/write semantics.

## Planned agents-cli command
When a network-enabled development environment is available:

```bash
agents-cli scaffold create teamgrit-work-agent --agent adk --prototype --agent-guidance-filename AGENTS.md
```

Then implement the tools and agent behavior defined above and run `agents-cli run` followed by `agents-cli eval run` before any deployment decision.
